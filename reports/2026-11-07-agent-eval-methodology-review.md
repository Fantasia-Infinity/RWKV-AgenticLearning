## 1. 实验设计（原文摘要）

- **题库 1019 题** = 首版 435 + 留出补题 135 + 第二轮自造 449；每题每个模型跑 **2 次**。
- 统计：先求每题平均，再在题目层面算误差；比较用**同题配对差 ±95% CI**。
- 泛化三档：已训回测 28 题 / 留出 951 题 / 开源 humanevalfix 40 题。
- 自造题由 Codex 生成、另一个 Codex 逐题审；参考答案在评测同款 Debian 容器 449/449 通过。
- 判分器修复：`required_tools` 中新工具名（read/grep/glob/bash）不能互相替代（旧工具名可以）→ 修 `bank/judge.py` 并用 `runner/rescore.py` 重判。
- 超时口径：adapter 推理慢约 4.5×，两边统一 **5 倍时限**（单轮 25 分钟），1 倍时限超时的 trial 用 5 倍补跑。
- 判据自审：R2（只读题偏宽）、R3（全角数字/千分位误判）、R4（名称局部命中偏宽）；报告估计对总分影响 <1pp。

## 3. 归因：涨分来自"工具调用行为"，不是推理

| 行为指标 | 基模 | adapter |
|---|---|---|
| 网页题打开网页比例 | ~35% | **~99%** |
| 代码修复"一个工具都不调" | 19% | **0%** |
| 工具报错率 | 22% | **8%** |
| 改测试文件次数 | 39 | 8 |
| 剩余失败"做了但做错" | — | **基本没减少** |

→ 该报告的核心结论是：SFT 教会了"按题面调对的工具"，但没有提升"做完之后做对"的能力。后者是 RL/在线优化的空间。

## 6. 方法评估

**可借鉴（7 条）**
1. 同题配对差 + 95% CI（避免不同题集比较的伪增益）。
2. 三档泛化（已训/留出/开源异构）。
3. 能力块 + 训练领域双维拆分（数据量 vs 涨幅）。
4. 机械 trace 统计（工具调用率、报错率、超时、收尾原因）。
5. 逐题归因码（17 批 × 16 类）。
6. 判据自审（偏差方向 + 影响估计）。
7. 超时口径明示（倍数 + 补跑）。

**局限**
- 无 LICENSE、Docker 依赖、私有 adapter/数据 → 不可复现，只能引用。
- 判据仍有偏宽/偏严项（已披露，估计 <1pp）。
- 自造题对 7B 区分度不足（327 题两边 0 分：easy 243 / medium 84 / hard 1）。
- 单模型、单 adapter、无 RL 对照。

## 7. 对 RWKV agent 训练/评测的直接启示（我们的设计清单）

**Harness / 工具协议**
1. 重复调用保护必须在 write/edit **之后重置**（否则"改完复检"被误杀）。
2. 工具错误要可恢复：报错信息应引导下一步（不同调用/不同参数），而不是直接收尾。
3. 思考长度预算：限制 `<think>` 长度，计数/过滤强制用工具（bash/awk/grep/python3 -c）。
4. "要求搜必搜"策略：题面要求搜索时必须调用检索；同时提供"不该搜"的对照样本，避免过度搜索。
5. "做不到"路径：零工具直答 + 替代建议；同时配"需先查本地再判断"的对照。
6. 多轮追问语义：追问涉及前轮未读内容时应重新查看；只复述时不必调用。

**数据**
7. 收尾数据要教"被拒后怎么答"（目标步为 0 是已知缺陷）。
8. 统计/日志类数据用工具计数，思考保持短。
9. 改写测试文件行为需要负样本约束。

**评测报告模板**
10. 配对差 + CI、三档泛化、能力块、trace 机械统计、逐题归因、判据自审、超时口径——这些应成为我们公开报告的最低标准。

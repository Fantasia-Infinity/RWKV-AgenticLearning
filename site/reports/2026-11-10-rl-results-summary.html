RWKV-7 G1l-1.5B agentic RL: consolidated results (2026-11-08 → 2026-11-10)

All numbers from our own runs on Snellius (A100-40GB). Code: this repo (Apache-2.0). Weights: RWKV-7 G1l-1.5B-20261031 (Apache-2.0). GSM8K used for evaluation/training only. Machine-readable copy: reports/data/2026-11-10-summary.json.

1. What was tested

Stage Setup Purpose

G3 tool-call eval 258 single-step tasks (held-in style) did SFT learn tool selection?
held-out tool benchmark 120 self-built tasks (calc/search/stats/direct, independent seed) generalization of tool selection

2. Headline results

✅ DAPO on plain GSM8K is the first positive RL result

  • avg@4 (200 questions, k=4, temp 1.0): 21.0% → 31.0% (+10.0pp, paired t=3.99, p=6.6e-05)
  • pass@4 unchanged (50.0% → 50.5%, p=1.0) → RL improves per-sample reliability, not coverage
  • last-5-checkpoint mean 29.5%; checkpoint variance ±5pp (small-batch DAPO)
  • Report: 2026-11-10-dapo-gsm8k-rlvr.md

⚠️ FlashREINFORCE RLVR (50 steps) is not significant

  • greedy pass@1: base 39.58% (1,319 q) → RL 41.39%; +1.81pp, McNemar p=0.29 — not significant
  • format rate 60.2% → 98.4% (the real, deterministic gain)
  • avg@4 metric: base 21.0% → 26.0% (suggestive but same small-sample caveat)

❌ Multi-turn tool RL (P3/P3c) underperforms SFT

Model GSM8K-calc accuracy (262) avg tool calls
base 3.4% 0.03
SFT warm start 42.0% 3.15
P3 RL (100 steps) 35.9% 1.44
P3c RL (50 steps, min-call shaping) 38.6% 2.97
  • Answer-only RL learns a tool-call shortcut (calls per sample drop 3.15 → 1.44) and loses accuracy
  • Held-out benchmark confirms degradation: tool-name accuracy 98.9% (SFT) → 82.2% (P3c), direct no-call rate 3.3% → 0%
  • No-KL constraint of FlashREINFORCE blocked the usual KL-regularized fix; reward shaping only partially recovered

✅ SFT tool-call ability generalizes

  • G3 tool-call tool-name accuracy: 21.6% (base) → 92.96% (SFT v3), parse rate 100%
  • held-out 120 tasks: tool-name 98.9%, argument validity 100%

3. Interpretation

  1. RLVR can work on RWKV-1.5B — but the recipe matters. FlashREINFORCE at 50 steps gave no significant greedy gain; DAPO at 1,000 steps gave a significant avg@4 gain (+10pp). The difference is consistent with the official report (g1k + 155 SFT + 1,000 DAPO steps: GSM8K avg@4 59.42 → 71.85, +12.4pp), though their scale is ~320× ours per step (upstream DAPO reference: 1,024 prompts × 5 samples = 5,120 rollouts/step vs our 16).
  2. SFT teaches format and tool selection extremely well (G3 +71pp, held-out 98.9%) but a short math SFT does not improve math accuracy (avg@4 21 → 17.5). RL then recovers and exceeds the base on sampling reliability.
  3. Multi-turn tool RL is the hard part. Answer-only rewards create shortcuts; no-KL FlashREINFORCE limits stabilizing tricks; held-out tool selection degrades. This is the clearest public negative result in the RWKV agentic-RL space and motivates process rewards / tool-call constraints / KL-capable algorithms for future work.
  4. Small-batch DAPO is noisy (±5pp). Report both final checkpoint and last-5 mean; do not over-read a single checkpoint.

5. Caveats

  • 200-question eval subset for avg@4 (1319 for greedy pass@1); single seed per configuration.
  • g1l-1.5B only; 2.9B/7.2B untested.
  • DAPO ran with dynamic_sampling=null (filter crashed on all-zero-variance batches); i.e. DAPO minus dynamic sampling.
  • External official numbers (59.42 → 71.85) are talk-level claims with undisclosed batch/GPU settings; not reproduced here.

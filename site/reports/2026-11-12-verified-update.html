2026-11-12 生态核验更新：SFT 数据打分的 58.7，以及 eval harness 三条 open PR

核验时间：2026-11-12 14:00–14:40 CET。方式：GitHub API + raw 文件回源。 对应外部摘要：2026-11-12 两轮日检（13:45 前后）。

一、已核验事实

1. rwkv-agent-eval 的 scores-20261111.md / loss-20261111.md

两个文件实际位于 docs/reports/（不是仓库根），内容与日检数字一致：

  • 基模是 rwkv7-g1l-7.2b-20261031-ctx34304（7.2B），旧 adapter 53.2，新 adapter g1l-nora-r16-261111 （mix-20261111：Agent 1714 条 + 日常 2911 行）58.7（+5.5 ±2.5 over 旧；+27.8 ±3.1 over 基模）； 12 个能力块 11 涨，terminal −3.3（误差内）。
  • 涨点：edit-data +16.7±10.7、stat +11.3±10.1、web-local +7.0、search +6.1；web-code/read-code/code-fix 基本未动。
  • 补测（rc.1 + 日期行）：新 adapter 57.3，对比 58.7 为 −1.5 ±2.1（区间跨 0） → 换到"训练时环境"没有多拿分。
  • 评测协议：1019 题 × 每题 2 次（合并补测后每题 4 次），超时算 0；本次两组均无超时/环境错误。
  • 该仓库无 LICENSE（GitHub API license: null）→ 数据/代码不可复用，只能引用数字。

2. loss-20261111.md 的失分拆解（比日检更细）

  • 失败 428 题（新模型）；失败原因：重复调用被强制收尾 23.8% + 用满 12 步 12.2% + 输出截断/格式坏 11.8% ≈ 47.8% 是"打转或失控"；真正做完答错约 30%。
  • 编辑工具错误率 27.7%（原文找不到 506 次、新旧内容相同 132、原文不唯一 8）；19.6% 的失败轨迹里至少一次编辑报错。
  • 打转集中的三块（web-code / code-fix / terminal）占全部失分 42%；terminal 是唯一退步块（训练集无此类题）。
  • hashline 零样本不会用：基模 18.3 → 1.9 分，仅 3% 的编辑调用写了新参数（插件分支 hashline-edit）。
  • 改提示词无效：416 道编辑题上改工具描述/加系统规则，编辑失败率仍 27.5–28.5%（基线 28.1%）。
  • 容错匹配离线重放：1094 次可靠还原的"原文找不到"里，Aider 式整段缩进对齐能救回 148 次（13.5%）； 其余约 72% 是内容本身抄错，只能换编辑方式或训练解决。

三、对我们项目的影响

  1. 失败分类高度一致：他们的"重复调用/用满步数/截断"正是我们 P3 多轮工具 RL 里观察到的打转与格式退化； 说明答案级奖励不足以修复行为层，需要硬约束（grammar/重复门）+ 接口设计（hashline 类）配合训练数据。
  2. hashline 的零样本失败给我们一个警示：新工具接口必须配训练轨迹（同我们在 PR #20 模板迁移上的教训）， 不能指望"改接口就自动变好"。
  3. 版本化 adapter 服务 + Megatron 原生 adapter 导出补齐了多 adapter 评测/异步 RL 的工程基础； 我们的 skyrl+vLLM 栈仍 pin FlashRWKV2 a17，升级 a19 前需做 parity（已列入 P4）。
  4. 评测仓库无 LICENSE、部分功能依赖未提交分支 → 公开交付继续只引用数字，不复制其代码/数据。

3. w1c2j3/rwkv-pi（客户端）

  • GitHub：TypeScript，created 2026-11-08，pushed 2026-11-27，★0，无 LICENSE（API license: null；仅 templates/LICENSE 为 Apache-2.0 模板许可）
  • 定位：把 RWKV 接入 Pi coding agent（@earendil-works/pi-coding-agent），Pi 的真实 loop/tools/sessions/terminal 不变， RWKV 通过 rwkv_lightning_cuda 以纯续写模型运行
  • 关键设计：
  • 训练/服务逐字节一致：同一 renderer + engine 原生 tokenizer 打包 SFT 数据（tokenizer 只走 Lightning 原生，不用 HF/irwkv/vLLM）
  • Line-Edit v2 + tolerant edit（v0.2 推荐；旧 v0.1 为 oldText/newText 协议）
  • 工具 read/write/edit/bash（grep/find/ls 可选）；重复失败/相同调用/单路径连续失败都有 hard limit
  • 插件：strong-model 教师接管（stall detector）、subagents
  • harness：真实 Pi + bubblewrap 沙箱；数据管线（Harbor lane、trajectory 打包）
  • 代码仓只放代码：README 明确"questions/trajectories/datasets/evaluation reports 留在私有存储"， 训练与评测需要私有 artifact；因此 Pi v0.2 的公开评测数字目前没有（11-27 commit "report cumulative v0.2 demo pass rates" 的产物也未公开）

5. 判断与对我们的影响

5.1 是什么 / 不是什么

  • 是：目前公开的最大规模 RWKV agent 模型族（7.2B，4 个 BF16 + 2 个 W8A16 checkpoint，含 Pi/DSH 两条线、公开评测卡、一键部署、公开数据集）。
  • 不是 RL：训练路线是 SFT → anneal → DAgger（on-policy 纠错，监督式）/ Line-Edit v2；没有 RLVR/GRPO 结果。 这与此前判断一致：公开 agent 成绩仍以 SFT 类为主。
  • "3×+" 的出处：最接近的是 DSH 私有 benchmark 上 base 13.96% → 49.04%（3.51×），但 benchmark 私有、且是 DSH 而非 Pi 线； 公开 Harbor 结果（Aider 4.4%、QuixBugs 5%）说明绝对能力仍有限。不可把 3× 当作公开可复现的 benchmark 结论。

5.2 与我们的实验对照

  1. 接口方向一致：Line-Edit v2 + tolerant edit + DAgger，正是我们 P3 负结果指出的"工具接口 + 行为修正数据"路线； 我们当时用 answer-only RL 得到 tool-call shortcut，他们用 DAgger/接口改造绕过——两条路线可以互补。
  2. 评测口径：他们用私有 PB benchmark + Harbor 公开子集；我们 P4 若要对标，应优先选 Harbor/Terminal-Bench 类公开任务， 避免私有 benchmark 的不可复现问题。
  3. 规模差异：这是 7.2B（14.4GB/ckpt）的 SFT 模型族；我们 1.5B 的 DAPO/SAO 是 RL 结果。两者只在"相对提升"层面可比， 不能直接比较绝对分。
  4. 许可：模型权重 Apache-2.0（可用）；rwkv-pi 客户端无 LICENSE（只能读，不能复用代码）； lightning 引擎 zip 是"作者许可再分发"但上游仓库无 LICENSE；trajectories 数据集 CC-BY-4.0（需署名）、bad cases Apache-2.0。
